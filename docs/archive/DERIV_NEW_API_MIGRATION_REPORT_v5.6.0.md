## Current authentication flow

1. Browser requests `/auth/deriv/login`.
2. Server generates a cryptographically random PKCE verifier.
3. Server derives S256 `code_challenge`.
4. Server stores verifier/state in an encrypted short-lived HttpOnly cookie.
5. Browser is redirected to `https://auth.deriv.com/oauth2/auth`.
6. Deriv redirects to the exact registered callback.
7. Server verifies state.
8. Server exchanges the code at `https://auth.deriv.com/oauth2/token`.
9. Server stores the access token only inside an encrypted HttpOnly cookie.
10. Server calls `GET /trading/v1/options/accounts`.
11. Server selects an available Options account.
12. Browser receives an opaque `proxy_<accountId>` marker only.
13. Browser opens `direct Deriv WebSocket transport`.
14. Server requests `POST /trading/v1/options/accounts/{accountId}/otp`.
15. Server connects to the returned `wss://api.derivws.com/trading/v1/options/ws/...`
    URL.
16. Browser trading messages are forwarded through the authenticated Options
    WebSocket.

## Security checks

- OAuth authorization code is exchanged server-side.
- PKCE state is checked.
- PKCE verifier never reaches the browser after login.
- Access token is never written to localStorage.
- Access token is never included in the WebSocket URL generated by the browser.
- Session cookie is HttpOnly.
- Production session cookie is Secure.
- Production session secret is required to be 32+ characters.
- Upstream WebSocket URLs are allowlisted to the current Deriv Options API.
- Risk gate runs server-side before proposal/buy forwarding.

## Trading compatibility

The existing DDBot execution layer continues to use the familiar Deriv
message vocabulary (`ticks`, `ticks_history`, `proposal`, `buy`, `sell`,
`proposal_open_contract`, `balance`, etc.).

Current Deriv documentation explicitly documents these operations for the
Options WebSocket workflow.

## Official API basis

This migration follows the current Deriv documentation for:

- OAuth 2.0 Authorization Code + PKCE
- `GET /trading/v1/options/accounts`
- `POST /trading/v1/options/accounts/{accountId}/otp`
- `wss://api.derivws.com/trading/v1/options/ws/demo?otp=...`
- `wss://api.derivws.com/trading/v1/options/ws/real?otp=...`
- proposal / buy / sell / proposal_open_contract trading operations

See the official Deriv developer documentation for the authoritative
schemas and current request/response details.
